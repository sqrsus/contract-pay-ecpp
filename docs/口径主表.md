# 口径主表（单一事实来源）

> 本表是评审意见「三项收敛动作」的第 1 项：把所有金额/比率的**定义、取数源、使用方**收在一处。
> 代码中每项只有一处实现，任何报告、界面、SQL 都必须引用它，不得各自重算。
> 修改口径时：先改本表 → 再改「唯一实现」→ 跑 `cargo test` 与 `ctp selfcheck`。

## 一、核心口径

| 指标 | 定义 | 唯一实现 | 使用方 | 说明 |
|---|---|---|---|---|
| 合同金额（暂定）`C` | `ct_contract.original_amount_cent`，V1.6 起可直接编辑，**不叠加变更** | `Contract::total_amount()` | 台账档案列、审减额、审计比对 | 审定后只作档案，不参与任何额度/比率计算 |
| 审计价 `AUD` | `ct_contract.audit_price_cent`；`NULL / 0 / 负数` 一律按**未审定**处理 | `Contract::audit_price()` | 有效基准、审减额、RPT-11 | 应用层归一，DDL 不加 CHECK 以免脏值阻塞保存 |
| 有效计价基准 `Base` | `AUD > 0 ? AUD : C`（审定后**完全替代**） | `Contract::effective_base()` | 额度、比率、余款、分类汇总 | BR-14 |
| 审减额 | `C − AUD`，仅已审定有意义；审增时为负 | `Contract::audit_reduction()` | 合同详情、对账表 | 派生，不落盘 |
| 累计已付 `P` | `SUM(pay_payment.amount_cent) WHERE status='PAID' AND is_deleted=0` | `schema::paid_net_subquery()` / `repo::paid_net()` | V1～V4、额度、报表 | **全系统唯一取数源**，本期直连 `pay_payment`，不经分摊表 |
| 在途 `F` | 本期无申请单，**恒为 0** | `PaymentQuota::compute(..., inflight)` | 额度 | 二期恢复审批后按「审批中全额 / 已批准减已付」两类占用 |
| 容差 `Tol` | **R-33 起业务口径恒为 0**：`Tol = 0`，上限即 `Base`。`sys_meta.tol_bp` 仅为兼容旧库保留，读取一律忽略 | `db::tolerance()`（恒返回 `Rate::ZERO`）→ `PaymentQuota::compute` | 拦截上限、越界提示 | BR-15；旧库曾写入的非 0 值不再生效，界面 / 命令行均无写入口 |
| 可付额度 `Avail` | `Base + Tol − P − F`（可为负） | `PaymentQuota::compute` | 视图、台账展示 | **视图口径**，不含付清条件限制 |
| 付清上限 `Cap` | 未登记交工日期 → `Base × 80%`；工程合同未审定、或交工日期距**开单日**未严格超过 2 个自然年 → `Base × 80%`；其余 → `Base × 100%` | `quota::pay_limit()` / `pay_limit_for()` | 拨款登记、拨款页额度卡、台账详情卡 | 80% 为**硬上限，不叠加容差** |
| 本期可付 `Payable` | `min(Base + Tol, Cap) − P − F`（可为负） | `PaymentQuota::compute` 的 `payable_amount` | **登记拨款的唯一拦截口径** | 视图 `available_cent` 仍是 `Avail`，不改口径 |
| 支付比率 | `P / Base`，万分比整数，四舍五入。**分母恒为有效计价基准**（已审定取审计价，未审定取合同金额），不是合同金额、不是付清上限、不是可付额度 | `Rate::ratio()`；SQL 侧 `schema::rate_bp_expr()` | 台账、一览、分类汇总、合同详情 KPI 卡 | **视图与应用层必须逐位一致（差异 0）**；`Base < P` 时（已超付）卡片转红并注明 |
| 越界标记 | `P > Base`（`P = Base` 为已付清，不算越界），**不含容差** | `PaymentQuota::is_inverted` / `V1.is_inverted` | 台账标红、CK-05 | 与拦截口径分工：拦截带容差，标记不带 |
| 越界级别 | 正常 / 已超有效计价基准 / 超付拦截（R-33 文案）；**容差固定 0 后中间态实际不可达**（`P > Base` 即超付拦截） | `PaymentQuota::breach_level()` | 界面提示 | 标记口径仍不含容差；core 层保留三态与 `tolerance` 参数便于纯函数单测，业务入口一律传 0 |
| 打印·已付款 | 本单之前累计已付：同合同、`status='PAID'`、按 `(pay_date, payment_no)` 严格小于本单；**作废单不计入** | `print::resolve` → `repo::paid_before_payment` | 打印件「目前已累计支付金额」「本期末累计支付金额」 | 按**开单日期**取数，不按打印当天 |
| 打印·金额形态 | 分 → 元，**截断保留两位小数**、无千分位（`1250000.00`） | `Money::fixed_yuan()` | 打印件 5 处金额位 | 与展示用的 `format_yuan()`（带千分位）严格区分 |
| 打印·合同价 | 「合同价」列固定取**合同价原值**（模板原域名为「合同改成元」） | `Contract::original_amount_cent` | 打印件第 2 页「合同价」 | 与有效计价基准无关，登记审计价后也不换 |
| 打印·可打印性 | 仅 `PAID` 状态可打印；作废单拒绝（入口不出现 + 生成前校验双保险） | `print::vouchers` | 三处打印入口 | 批量只合并已付单，作废单不可勾选 |
| 打印·结果反馈（R-42 / R-44） | `Ok(pages > 0)` → **已提交**弹窗（打印件名 / 单据张数 / 输出页数 / 提交时间，5 秒自动关闭）；`Ok(0)` 用户取消 → 静默；`Err` → **失败**弹窗（沿用 R-42 分类 / 文案 / 去重，仅手动关闭）。两态互斥且失败优先，提示在场时禁止再次发起打印 | `success_for_outcome()` / `failure_for_outcome()` / `print_busy()` / `offer_print_failure_exclusive()` | 预览窗「打印」按钮与三个打印入口 | `EndDoc` 成功只代表作业提交 Windows 打印队列，**不等于纸张物理出完**；文案一律「已提交 / 已发送」，不写「已完成」；提交时间取东八区本地时间，仅展示用，审计列仍写 UTC |
| 导出·台账列选择（R-46） | 「导出 Excel」先弹列选择窗（默认全选 9 列、可勾选 / 上移下移 / 全选 / 全不选 / 恢复默认 / 取消）；确认后 Excel **只含所选列**，表头文字与列顺序与选择结果逐字一致 | `ReportResult::select_columns()` / `ExportColumnsView` / `Dialog::ExportColumns` | 「合同台账」页「导出 Excel」 | 点按钮瞬间按当前搜索词 + 项目状态筛选后的行序快照完整结果，弹窗期间不重查库；金额列表头含「（元）」，选择列表与 Excel 用同一个 `ReportColumn::excel_title()` |
| 导出·拨款合同字段（R-46） | 拨款一览导出的 Excel 追加「合同名称」「承包单位」两列，按每行 `contract_id` 关联 V1 汇总行取值；**查不到或字段为空写空串，不跳行、不报错** | `ReportResult::payment_ledger_export()` / `payment_contract_lookup()` | 「拨款管理」页「导出 Excel」 | 与屏幕明细表共用同一套取数 / 合计逻辑，屏幕仍保持 5 列；作废单仍保留行、不计入合计 |
| 导出·公共链路与校验（R-46） | 两个入口共用 `App::save_report()`（保存框 / 取消静默 / `导出失败：{e}` / 成功文案）与 `service::write_and_log()`（写 xlsx + EXPORT 审计）；写文件前做形状校验 | `ReportResult::validate_shape()` / `ReportColumnError` | 报表导出 | 拒绝空选择、重复列、未知列、零列、数据行 / 合计行与列数不符；审计 detail 内容与留痕次数不变；权限校验（浏览可导出）不变 |
| 合同·计划交工自动计算（R-50） | 工期与计划开工**都有效**（工期为正整数、开工为合法 `YYYY-MM-DD`）时，计划交工 = **计划开工 + (工期 − 1) 天**（含开工当日；工期 1 天即当天）；任一无效则**不触发、不改动、不报错** | `contract::planned_end_for()` / `date::plus_days()` / `auto_planned_end()` | 新建合同页、信息修改弹窗 | 新建页与修改页共用同一规则；手改交工日后停止同步（值 ≠ 上次自动值即视为手改），字段下方提示「已手动修改，不再随工期自动同步」，清空后恢复自动；自动值仍须满足库约束 `planned_end >= planned_start` |

## 三、本期范围（与评审 M5 一致）

* 合同状态只产生 5 态：`DRAFT / ACTIVE / PERFORMING / COMPLETED / VOID`；
  `PENDING / SETTLED / CLOSED` 保留在 DDL 与枚举中，但**本期任何流转都被拒绝**。
* 拨款单状态只有 2 态：`PAID / VOID`。红冲（`REVERSAL/REVERSED`）与 `reversal_of` 已移除（H5），
  错误单据用「作废 + 重登」修正，作废后不计入 `P`。
* 不建 `pay_application` / `pay_application_item` / `pay_approval_log` / `pay_payment_allocation`（H3）。
* P0 必须属于本期范围，台账见 `ctp_core::scope::PLAN`，`ctp plan` 与 `selfcheck` 会校验。
