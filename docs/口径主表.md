# 口径主表（单一事实来源）

> 本表是评审意见「三项收敛动作」的第 1 项：把所有金额/比率的**定义、取数源、使用方**收在一处。
> 代码中每项只有一处实现，任何报告、界面、SQL 都必须引用它，不得各自重算。
> 修改口径时：先改本表 → 再改「唯一实现」→ 跑 `cargo test` 与 `ctp selfcheck`。

## 一、核心口径

| 指标 | 定义 | 唯一实现 | 使用方 | 说明 |
|---|---|---|---|---|
| 合同金额（暂定）`C` | `ct_contract.original_amount_cent`，V1.6 起可直接编辑，**不叠加变更** | `Contract::total_amount()` | 台账档案列、审减额、审计比对 | 审定后只作档案，不参与任何额度/比率计算 |
| 审计价 `AUD` | `ct_contract.audit_price_cent`；`NULL / 0 / 负数` 一律按**未审定**处理 | `Contract::audit_price()` | 有效基准、审减额、RPT-11 | 应用层归一，DDL 不加 CHECK 以免脏值阻塞保存 |
| 有效计价基准 `Base` | `AUD > 0 ? AUD : C`（审定后**完全替代**） | `Contract::effective_base()` | 额度、比率、余款、分类汇总 | BR-14 |
| 审减额 | `C − AUD`，仅已审定有意义；审增时为负 | `Contract::audit_reduction()` | 合同详情、对账表 | 派生，不落盘 |
| 累计已付 `P` | `SUM(pay_payment.amount_cent) WHERE status='PAID' AND is_deleted=0` | `schema::paid_net_subquery()` / `repo::paid_net()` | V1～V4、额度、报表 | **全系统唯一取数源**，本期直连 `pay_payment`，不经分摊表 |
| 在途 `F` | 本期无申请单，**恒为 0** | `PaymentQuota::compute(..., inflight)` | 额度 | 二期恢复审批后按「审批中全额 / 已批准减已付」两类占用 |
| 容差 `Tol` | `Base × tol_bp / 10000`，`tol_bp` 存 `sys_meta`，默认 0 | `db::tolerance()` + `Money::mul_rate` | 拦截上限、越界提示 | BR-15 |
| 可付额度 `Avail` | `Base + Tol − P − F`（可为负） | `PaymentQuota::compute` | 视图、台账展示 | **视图口径**，不含付清条件限制 |
| 付清上限 `Cap` | 未登记交工日期 → `Base × 80%`；施工合同未审定、或交工日期距**开单日**未严格超过 2 个自然年 → `Base × 80%`；其余 → `Base × 100%` | `quota::pay_limit()` / `pay_limit_for()` | 拨款登记、拨款页额度卡、台账详情卡 | 80% 为**硬上限，不叠加容差** |
| 本期可付 `Payable` | `min(Base + Tol, Cap) − P − F`（可为负） | `PaymentQuota::compute` 的 `payable_amount` | **登记拨款的唯一拦截口径** | 视图 `available_cent` 仍是 `Avail`，不改口径 |
| 支付比率 | `P / Base`，万分比整数，四舍五入 | `Rate::ratio()`；SQL 侧 `schema::rate_bp_expr()` | 台账、一览、分类汇总 | **视图与应用层必须逐位一致（差异 0）** |
| 越界标记 | `P > Base`（`P = Base` 为已付清，不算越界），**不含容差** | `PaymentQuota::is_inverted` / `V1.is_inverted` | 台账标红、CK-05 | 与拦截口径分工：拦截带容差，标记不带 |
| 越界级别 | 正常 / 容差内 / 超容差 | `PaymentQuota::breach_level()` | 界面提示 | 容差内：标红放行并提示；超容差：拦截 |

## 二、两套分类字典（评审 H4）

| 体系 | 落地位置 | 取值 | 谁在用 |
|---|---|---|---|
| 合同类别（业务口径） | `sys_dict_item`，`dict_type='CONTRACT_CATEGORY'` | `GC 工程款 / SB 设备款 / CL 材料款 / FW 监理费 / JC 检测费` | 合同登记下拉、台账筛选 |
| 会计分类（财务口径） | `ct_category`（`category_code` C01–C99） | `C01 前期费用 … C07 其他支出` | 分类汇总 RPT-02、清单行分摊、分类占比 |

**约束**：两套编码空间不得重叠（`dict::tests::合同类别与会计分类编码不重叠`）；
合同类别不得写入 `ct_category`（`consistency.rs::会计分类与合同类别分离`）。

## 三、本期范围（与评审 M5 一致）

* 合同状态只产生 5 态：`DRAFT / ACTIVE / PERFORMING / COMPLETED / VOID`；
  `PENDING / SETTLED / CLOSED` 保留在 DDL 与枚举中，但**本期任何流转都被拒绝**。
* 拨款单状态只有 2 态：`PAID / VOID`。红冲（`REVERSAL/REVERSED`）与 `reversal_of` 已移除（H5），
  错误单据用「作废 + 重登」修正，作废后不计入 `P`。
* 不建 `pay_application` / `pay_application_item` / `pay_approval_log` / `pay_payment_allocation`（H3）。
* P0 必须属于本期范围，台账见 `ctp_core::scope::PLAN`，`ctp plan` 与 `selfcheck` 会校验。
