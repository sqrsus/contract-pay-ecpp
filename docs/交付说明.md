# ctp-gui 可执行文件（交付说明）

生成时间：2026-11-05
源码版本：工作区 `D:\pay2`（Rust 1.99，edition 2021，SQLite 以 bundled 方式静态编入）

## 一、文件清单

| 文件 | 大小 | 说明 |
|---|---|---|
| `ctp-gui.exe` | 22.0 MB | **图形界面版**，双击即用，含中文字体、打印模板与全部本期功能 |
| `data\ctp.db` | 200 KB | 界面默认使用的数据库（exe 同级 `data` 目录），已含演示数据 |
| `demo.db` | 184 KB | 同一份演示库的副本，可拷成 `data\ctp.db` 覆盖，恢复到初始演示状态 |

单一二进制，`cargo build --release` 构建；Windows 版用本机 MinGW-w64 gcc 16.1 作为 `cc` 链接 SQLite。
无需安装任何运行时，也没有 WebView / 前端框架依赖。

## 二、使用说明

双击 `ctp-gui.exe` 即可。首次启动若 `data\ctp.db` 不存在，会自动建库并写入基础字典。

**六个页面**（左侧导航切换）：

| 页面 | 内容 |
|---|---|
| 总览 | 8 项关键指标（总合同数 / 履行中 / 归档关闭 / 合同金额合计 / 有效计价基准 / 累计已付 / 综合支付率 / 超付风险）、整宽「最近拨款」（带表头；点击合同名称跳到台账；行内「打印拨款单 / 打印附件」为文字链，作废单置灰）、右上「新建合同 / 新建拨款」，「载入演示数据」入口 |
| 合同台账 | 搜索 / 项目状态筛选、合同明细（审计价 / 交工日期列；点击编号查看只读详情，点击名称展开拨款明细——带表头、与拨款管理同列、已作废条目不再列出，点空白处收起）、右侧详情卡（附件、登记审计价、项目交工、去拨款） |
| 拨款管理 | 合同改为「输入编号或名称即筛查」的联想框（聚焦不全量展开，唯一命中自动切换），其后紧跟项目状态标签（履行中绿 / 归档关闭红）与支付率进度条；四张额度卡（基准 / 已付 / 可付额度 / 单据数）+ 登记表单（金额框右侧「付清」）+ 拨款明细（含勾选列与「批量打印所选」）；每行「打印拨款单 / 打印附件」 |
| 分类汇总 | 按会计分类的 V3 汇总，含合计行与支付进度；右上角「导出 Excel」 |
| 期间统计 | 按月份的 V4 柱状图 + 明细表，含占比列；右上角「导出 Excel」 |
| 自检与设置 | 六项口径自检、超付容差设置、数据源路径 |

**付清条件（本版新增）**：

- **所有未登记交工日期的合同**：累计已付不得超过有效计价基准的 **80%**，硬上限、不叠加容差；
- **施工类合同**：还须已登记审计价、且交工日期距本次**开单日期严格超过 2 个自然年**，才允许付到 100%；
  未满足时同样按 80% 封顶（已交工但未满 2 年也不放行）；
- 拨款管理页会直接给出受限原因与「当前累计上限 X% / 已付 Y 元」，可付额度与「付清」按钮都按封顶后的口径计算；
- 合同台账详情卡的「支付率」后标注「（上限 80%）」，可付额度同步按封顶口径显示。

**交互细节**：

- 窗口可自由缩放，最小 1100×720；宽度小于 1100 时左侧导航自动折叠为两字缩写，悬停显示全名；
- 右上「切换深色 / 切换浅色」在浅色与深色两套配色间切换，立即生效；
- 按钮有常态 / 悬停 / 按下 / 禁用四态；必填未填或金额非法时，提交按钮直接置灰，不用点了才报错；
- 弹窗打开时背景压暗，表单字段分两栏排布，小屏也不截断按钮；
- 新建合同分两步（基本信息 → 附件）；所属项目 / 承包单位 / 发包人都是带联想的输入框，
  输入库里没有的新名称会自动建档；
- 附件四类分项、每类一份，文件存进数据库，单份上限 50 MB；合同附件为必传项，卡点在「设为生效」；
- **报表导出**：分类汇总 / 期间统计两页的「导出 Excel」用 `rust_xlsxwriter` 生成单页 .xlsx，
  表头加粗、冻结前三行、金额 `#,##0.00`（单位元）、合计用 `SUM` 公式，并写一条 `EXPORT` 审计日志；
  屏幕表格与导出共用同一份 `ReportResult`，口径不会分叉；
- **付款打印**：拨款单 → 「打印拨款单」弹出核对窗（9 个合并域的取值与来源，含本次金额中文大写），
  三个出口：**打开并打印**（生成 docx 交给本机 Word，在 Word 里按 Ctrl+P 弹系统打印对话框出纸）、
  **导出 Word**、**导出 PDF**（由本机 Word 固定版式导出）。
  模板打包在程序内（`crates/ctp-app/templates/payment_voucher.docx`），9 个 MERGEFIELD 按域边界整体
  替换为纯文本，生成后自检残留占位符，一旦残留即报错中止、不打开打印；
  **作废单不允许打印**；**批量**在拨款明细里勾选若干条后点「批量打印所选」，合并成一份、每张一页；
- **打印附件**：附件按原件打开（用本机 Word / PDF 阅读器打开后自行选择打印范围），
  系统不接管附件打印、不做合并、不批量；
- 底部状态栏常驻提示（成功绿色、失败红色），右侧显示当前超付容差。

**排查用的环境变量**（一般用不到）：

```
set CTP_SCREEN=payments     启动直接进某个页面
set CTP_THEME=dark          启动即深色
set CTP_DIALOG=new_contract 启动即打开某个弹窗（另有 attachments / payment_detail / print_preview / print_batch / material_print / audit_price / edit_amount / void_payment / contract_detail）
set CTP_STEP=1              与 new_contract 配合，直达第二步（附件）
set CTP_SELECT=1            启动即选中第一份合同（看详情卡）
set CTP_EXPAND=1            启动即选中并展开第一份合同的拨款明细
set CTP_PAY_NO=HT-2026-002  拨款页直达指定编号的合同
set CTP_SELFTEST=1          跑满 40 帧后自动退出，并在 exe 同级写 smoke.txt
```

`CTP_SELFTEST` 是无界面验证手段：退出码 0 且 `smoke.txt` 里 `ok` + 数据条数正常，说明窗口与渲染管线都在正常工作，
适合在远程桌面或窗口被遮挡、截不到图的环境里快速确认程序本身没坏。

## 四、已知限制

- 合同编号仍为三位流水（`HT-2026-001`），文档 4.2.4 目标态为四位，二期迁移时统一切换；
- 图形界面单文件 22 MB，主要体积来自静态编入的 SQLite、中文字体与内置打印模板所需依赖，属正常；
- 本期不含支付申请、三级审批、红冲、结算、造价指标、RBAC —— 均为评审确认的延期项（见 `docs/口径主表.md` C 节）；
- **交付形态只有 GUI**，无命令行版本（R-25 决策）；
- **不做清单明细**（`ct_contract_item` 空表与 V3 分摊分支保留但无录入入口），也**不支持未分类暂存于草稿**（R-25 决策）；
- **付款打印只有一套模板**（打包在程序内，改模板需重新发版）：模板里的会计分类名 / 附件张数 / 当前日期
  三处按确认口径保持空白，需手工填写；打印件交给本机 Word 出纸，**本机必须装有 Microsoft Word**
  （导出 PDF 同样依赖 Word）；附件打印只是「打开原件」，不接管打印范围；
- 报表导出只覆盖 V3 / V4 两页，合同台账 / 拨款一览尚未接入 `ReportResult`。
