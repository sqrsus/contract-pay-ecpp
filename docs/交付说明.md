## 二、使用说明

双击 `ctp-gui.exe` 即可。首次启动若 `data\ctp.db` 不存在，会自动建库并写入基础字典。

**登录（本版新增）**：启动先到登录页，两个按钮 ——

| 按钮 | 行为 | 权限 |
|---|---|---|
| 浏览登录 | 免密直接进 | **只读**：可看全部页面与弹窗、可导出 Excel，但**任何写操作都会提示「无权限」**（不置灰，点了才提示）；导航里不出现「自检与设置」 |
| 管理登录 | 展开密码框，初始密码 `0001` | 全部权限，含登记 / 作废 / 修改密码 |

- 登录状态**只存在内存**，关掉程序即失效（下次启动重新选身份，不跨重启保持）；
- 密码以「加盐 SHA-256」存入数据库 `sys_meta`（键 `auth.admin_password`），**库里不存明文**；首次启动自动写入初始密码，已有密码不会被覆盖；
- 顶栏右侧常驻身份徽标（浏览用户 / 管理员）与「退出」，退出即回到登录页；
- 改密码在「自检与设置 → 管理密码」：需先输旧密码，新密码 4–20 位、两次一致，校验通过才落库；
- **原有数据零影响**：不新增表、不改表结构、不加列，密码只占 `sys_meta` 一行，旧库直接可用。

**六个页面**（左侧导航切换）：

| 页面 | 内容 |
|---|---|
| 总览 | 8 项关键指标（总合同数 / 履行中 / 归档关闭 / 合同金额合计 / 有效计价基准 / 累计已付 / 综合支付率 / 超付风险）、整宽「最近拨款」（带表头 + 24px 勾选列；**点合同名称弹合同详情**、点单号看拨款详情；与拨款管理一致的「批量打印所选（N）/ 全选 / 清空」文字链；行内「打印拨款单 / 打印附件」为文字链，作废单置灰）、右上「新建合同 / 新建拨款」，「载入演示数据」入口 |
| 合同台账 | 搜索 / 项目状态筛选、合同明细（审计价 / 交工日期列；点击编号查看只读详情，点击名称展开拨款明细——带表头、与拨款管理同源、已作废条目不再列出，点空白处收起）、**合计行**、「导出 Excel」（**R-46：先选列、可调序，Excel 只写所选字段**）、右侧详情卡（附件、登记审计价、项目交工、去拨款）；**「承包单位」列宽为本版加宽后的 1.5 倍**（避免长单位名被截） |
| 拨款管理 | 合同改为「输入编号或名称即筛查」的联想框（聚焦不全量展开，唯一命中自动切换），其后紧跟项目状态标签（履行中绿 / 归档关闭红）与支付率进度条；四张额度卡（基准 / 已付 / 可付额度 / 单据数）+ 登记表单（金额框右侧「付清」）+ 拨款明细（含勾选列、「批量打印所选」与**合计行**）；每行「打印拨款单 / 打印附件」；页头新增「导出批量拨款模板 / 导入批量拨款 / 导出 Excel」（**R-46：导出的 Excel 带「合同名称」「承包单位」两列**） |
| 汇总统计 | **四个维度**：按项目 / 按承包单位 / 按合同 / 按合同类型（按日已删）；统计区间留空 = 不限，另有「本月 / 本年 / 全部时间」快捷；**筛选**：项目状态（履行中 / 归档关闭）、合同类型、关键词（项目 / 承包单位 / 合同）；柱状图 + 明细表 + 占合计列，按合同维度单独多一列承包单位；右上角「导出 Excel」 |
| 操作日志 | **本版新增，仅管理员可见**：所有写库操作的留痕（时间 / 操作类型 / 对象类型 / 操作对象 / 操作内容 / 操作人），可按日期区间、操作类型、关键词筛选；提供「按时间段清理 / 全部清理」，二次确认后执行，**清完自动留一条清理记录** |
| 自检与设置 | 六项口径自检、数据源路径、**管理密码修改**（超付容差固定 0，界面无配置入口；浏览用户不进此页） |

**合同详情弹窗（本版重排）**：

- 顶部四张 KPI 卡：合同金额 / 审计价 / 累计已付 / 支付率（基准低于已付时支付率数值标红）；卡片**不再带任何辅助说明文字**，四卡等高；
- 去掉了「计价方式」一行与「合同主体 / 招标与工期 / 价款与条款」三处分栏标题，改用分隔线分组；
- 左卡合并为「双方 + 招标与工期」，右卡为「属性 + 条款备注」；弹窗整体宽 1060 → **960**（更紧凑）。

**批量导入拨款（本版新增）**：

1. 「导出批量拨款模板」：从库里读全部合同生成 .xlsx，9 列 = 合同名称 / 承包单位 / 合同价 / 审计价 / 累计已付（**前 5 列预填只作核对**）+ 本次金额 / 开单日期 / 事由 / 支付方式（**后 4 列待填**）；
2. 模板内嵌一张**隐藏工作表 `_CTP_CHECK`**，A1 写校验标记 `CTP-BATCH-PAYMENT-V1`；导入时先比对，**缺失或不一致整份拒绝**，防止拿别的表改改列名就传上来把账写坏；
3. 「导入批量拨款」：按**合同名称严格匹配**（同名多份直接报「对应 N 份，无法确定」），逐行校验金额 / 日期 / 支付方式；
4. **本次金额为 0 或留空跳过**（不算失败）；**日期留空按当天**、**事由留空按「拨付进度款」**、**支付方式留空按转账**；
5. **逐行跳过并报错**：某行不合格只跳过该行；导入后弹出**常驻结果弹窗**（真模态，只有「关闭」能退出，刷新 / 切主题 / Esc / 点弹窗外都不关），
   顶部给出「成功导入 N 笔 · 跳过 M 行 · 失败 K 行」，下面逐条列出**行号 + 失败原因**，不列逐行明细；
   成功 / 部分失败 / 全部失败 / 整份拒绝（缺校验表、标记不符、文件打不开）都用同一个弹窗。

**付清条件**：

- **所有未登记交工日期的合同**：累计已付不得超过有效计价基准的 **80%**，硬上限、不叠加容差；
- **施工类合同**：还须已登记审计价、且交工日期距本次**开单日期严格超过 2 个自然年**，才允许付到 100%；
  未满足时同样按 80% 封顶（已交工但未满 2 年也不放行）；
- 拨款管理页会直接给出受限原因与「当前累计上限 X% / 已付 Y 元」，可付额度与「付清」按钮都按封顶后的口径计算；
- 合同台账详情卡的「支付率」后标注「（上限 80%）」，可付额度同步按封顶口径显示。

**交互细节**：

- 窗口可自由缩放，最小 1100×720；宽度小于 1100 时左侧导航自动折叠为两字缩写，悬停显示全名；
- 右上「切换深色 / 切换浅色」在浅色与深色两套配色间切换，立即生效；
- 按钮有常态 / 悬停 / 按下 / 禁用四态；必填未填或金额非法时，提交按钮直接置灰，不用点了才报错；
- 弹窗打开时背景压暗，表单字段分两栏排布，小屏也不截断按钮；
- 新建合同分两步（基本信息 → 附件）；所属项目 / 承包单位 / 发包人都是带联想的输入框，
  输入库里没有的新名称会自动建档；
- 附件四类分项、每类一份，文件存进数据库，单份上限 50 MB；合同附件为必传项，卡点在「设为生效」；
- **报表导出**：「汇总统计」「合同台账」「拨款管理（拨款一览）」三页的「导出 Excel」都用 `rust_xlsxwriter` 生成单页 .xlsx，
  表头加粗、冻结前三行、金额 `#,##0.00`（单位元）、合计用 `SUM` 公式，并写一条 `EXPORT` 审计日志；
  **屏幕表格、合计行与导出共用同一份 `ReportResult`**（列配置驱动），口径不会分叉；
  合同台账窄屏降列只影响屏幕；**R-46 起导出前可选列并可调整顺序**（默认全选 9 列），Excel 只写所选字段，
  数据仍取当前筛选 / 排序后的列表结果；拨款一览按当前合同导出、合计排除作废单，并额外带
  「合同名称」「承包单位」两列（按 `contract_id` 关联，缺失留空）；
- **付款打印**：三个入口（总览最近拨款、合同台账行内、拨款管理行内）调用同一套逻辑 ——
  先弹**核对窗**（左侧为真实位图预览、可翻页，右侧列出 9 个合并域的取值与来源，含本次金额中文大写），
  点「打印」直接弹 Windows 系统打印对话框出纸。
  **不经过 Word、Edge、PDF 阅读器等任何外部软件**：版面由程序按模板逐线复刻（`paper.rs`），
  用 GDI 画到打印机 DC 上，版面写在程序内，因此版式不随本机 Office 版本漂移，启动也是毫秒级；
  核对窗里的预览图与出纸走**同一份版面代码**，所以预览即成品；
  **纸型必须 A4 横向**：若对话框首选项是纵向，程序取到打印机后会立刻拦下并提示改纸型（不裁切、不打半张）；
  **作废单不允许打印**；**批量打印**在总览「最近拨款」与拨款明细里勾选若干条后点「批量打印所选」，两处共用同一套勾选集合与打印逻辑，合并成一份、每张一页；
  **结果反馈（R-42 / R-44）**：成功弹「打印已提交」卡片（打印件名 / 单据张数 / 输出页数 / 提交时间 + 取件核对提醒，5 秒自动关闭、可提前「关闭」），
  失败弹「打印失败」卡片（原因类型 / 失败原因 / 建议操作 / 技术信息，仅「关闭」退出）；用户取消对话框不弹任何提示。
  两者均为叠加层、不占用预览弹窗，关闭后单据 / 页码 / 预览图原样保留，失败优先且同一时间只有一个提示，提示在场时「打印」按钮置灰防重复出纸。
  前置校验（未勾选 / 无可打印单据 / 数据库未打开）仍走底部提示条；其他模块的提示条行为不变；
- **打印附件**：按原件交给系统默认程序打开（Word / PDF 阅读器均可），由用户在软件里自行选择打印范围，
  程序不接管附件打印、不做合并、不批量；
- 底部状态栏常驻提示（成功绿色、失败红色），右侧显示当前登录身份（超付容差固定 0，不再显示）。
  **例外**：打印成功 / 失败不再走状态栏，改走各自的卡片弹窗（见第七节）；打印的前置校验仍用普通提示条。

**排查用的环境变量**（一般用不到）：

```
set CTP_SCREEN=payments     启动直接进某个页面（dashboard / contracts / payments / summary / logs / checks）
set CTP_THEME=dark          启动即深色
set CTP_LOGIN=admin         跳过登录页，直接以管理员身份进入（调试用）
set CTP_ROLE=browse         跳过登录页，直接进浏览模式；配 CTP_SCREEN=checks / logs 会被强制退回总览
set CTP_DIALOG=new_contract 启动即打开某个弹窗（另有 attachments / payment_detail / print_preview / print_batch / material_print / audit_price / edit_amount / void_payment / contract_detail）
set CTP_STEP=1              与 new_contract 配合，直达第二步（附件）
set CTP_SELECT=1            启动即选中第一份合同（看详情卡）
set CTP_EXPAND=1            启动即选中并展开第一份合同的拨款明细
set CTP_PAY_NO=HT-2026-002  拨款页直达指定编号的合同
set CTP_SELFTEST=1          跑满 40 帧后自动退出，并在 exe 同级写 smoke.txt
```

`CTP_SELFTEST` 是无界面验证手段：退出码 0 且 `smoke.txt` 里 `ok` + 数据条数正常，说明窗口与渲染管线都在正常工作，
适合在远程桌面或窗口被遮挡、截不到图的环境里快速确认程序本身没坏。

## 二十、R-61 跨滚动切换展开目标失效的修复 + 版本 0.4.4（2026-11-10，含发布版重建）

- **现象**：先展开一条（A），滚到视口外的另一条（B）再点它的「累计已付」或「承包单位」，A 先缩回，B 错位、失去焦点，最终不展开；两条都在同一可视区域内时正常。
- **根因**：台账页在 `draw()` **第一行**就执行「点在面板外就收起」，即在按下那一帧、绘制与命中测试之前改了状态。于是按下帧的表格已经少掉 A 面板的高度：其后的行整体上移、靠近底部时滚动偏移又被重新钳制，指针落点与新的行错位；指针一旦被追着微调超过 6 px，这次操作就从「点击」降级成「拖拽」，`potential_click_id` 作废，B 从未收到展开请求。点击本身要到释放帧才成立，所以帧首判定只能拿到「点了面板外」、拿不到「点的是哪个入口」，中间必然夹着「A 已收起、B 未展开」的空档。
- **为什么同视区内正常**：A 在渲染顺序上位于 B 之后时，收起 A 不改变 B 的矩形，指针不用动；而「滚动后才可见」的目标必然排在已展开条目之后，因而必然失败。
- **修复（三处，按确认口径）**：
  1. **判定移到释放帧、状态转移移到帧末**：`click_outside` 改用 `pointer.any_released()`，与 `clicked()` 同帧可得；收起与展开在同一帧末一次算清（`should_collapse_panels`），不再有中间态。按下帧完全不改状态，命中与点击判定都落在用户实际看到的那一版布局上。
  2. **偏移预修正**：点击帧末算出被收起面板的高度（`offset_fix_for`，仅当它在目标行之上），下一帧构造列表时用 `vertical_scroll_offset(上帧偏移 - 面板高)` 直接补掉，切换那一帧就不跳。
  3. **滚动锚定兜底**：记下被点行点击时的屏幕纵坐标（`pending_expand_anchor`），下一帧渲染到该行时按残差用 `scroll_with_delta` 补齐（`anchor_delta`，正数 = 内容下移）；预修正已精确时残差为零、不再滚动。

## 二十一、R-62 展开后未滚入视口的落位补偿 + 版本 0.4.5（2026-11-10，含发布版重建）

- **根因**：列表滚动只有三处写入 —— `pending_offset_fix`（减掉被收起面板高度）、`pending_expand_anchor`（把被点行拉回原屏幕位置）、用户滚轮。前两者的目标与「滚入视口」严格相反：它们要**把被点击的行钉在原处、不许跳**。行被钉死，面板只能往下长；行只要落在视口下半部（行高约 26 px、面板 100~300 px、列表可视高约 500 px），面板就整块长在下边界之外。连续点击放大这个必然性：第一次展开把后续行整体推下去，第二次点的行更靠下，钉住后面板必然完全在视口外。同视区正常是同一机制的另一面——那时面板还放得下。
- **附带缺陷**：锚定补偿在**行顶部**发出 `scroll_with_delta`，而该行面板里的 `TableBuilder::body()` 自带一层 `ScrollArea`，它在 `end()` 里无条件 `take` 掉本帧滚动指令（egui 0.29 `scroll_area.rs:820`）。所以展开帧的锚定常被这层内嵌滚动区吞掉，真正生效的只有 `pending_offset_fix`；目标行在已展开行下方时它为 0，那一帧就完全没有定位动作。
